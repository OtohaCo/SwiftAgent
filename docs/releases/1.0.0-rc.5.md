# SwiftAgent 1.0.0-rc.5

> Release type: SDK prerelease candidate. This is not stable 1.0, and it does
> not approve any production Host or store cutover. The GitHub Pre-release
> records the exact tagged commit and its final verification.

RC5 builds on RC4. It adds two opt-in capabilities and fixes defects found by
review of the post-RC4 work. It has no new default behavior for Hosts that do
not opt in, except for the fixes and behavior changes listed below.

- **Bounded pre-admission replanning (opt-in, off by default).**
  `AgentConfiguration.preAdmissionReplanning` defaults to `.disabled`.
  - **Opt-in:** use `.evidenceRejection(toolNames:)` to name the mutation
    tools that may take part.
  - **What it does:** when the runtime's own first Evidence check rejects a
    single prepared call to one of those tools, before authorization, durable
    intent or execution admission, the model gets **one** correlated error
    result in the same Run. It can then correct itself.
  - **Budgets:** the rejected proposal uses one tool-call attempt. The
    correction runs inside the **original Run and its remaining turn,
    tool-call and deadline budgets**, with the same capability scope. No
    second Run is started, and the budget is not reset.
  - **What the denial is not:** it is not a Receipt, Evidence, authorization
    or a tool execution.
  - **Where it does not apply:** multi-call responses, earlier effects,
    unresolved operations, failed status reads and every later gate keep
    their RC4 failure or reconciliation paths. A second missing reference in
    the same Run is an ordinary failure. See
    [ADR 0008](../adr/0008-bounded-pre-admission-replanning.md).
- **Tools defined at runtime.** `AgentTool` gains `definition`, which defaults
  to the type's static name, description and schemas. The new `RuntimeAgentTool`
  (JSON input and output) supplies `runtimeDefinition`, so one type can serve
  tools whose names are known only at runtime.
  - The registry, schema validation, capability bindings and mutation admission
    all use the **instance** definition.
  - A capability binding reads the definition **once, when the binding is
    created**, and uses that snapshot for the binding's lifetime. Changing
    what an instance returns later does not change an existing binding.
  - A runtime name must be 1–64 letters, digits, `_` or `-`.

## Fixes

- **Route continuation isolation.** `ModelProviderRoute` returns opaque
  continuation state, such as encrypted reasoning, only to the candidate that
  produced it.
  - If the owner fails or is not a current candidate, the request fails with
    `fallbackBlocked` before any other candidate is contacted.
- **Steering durability.** Corrections accepted by `run.steer` but not yet
  delivered when a Run is cancelled or fails are committed with their IDs
  before the Run ends. RC4 kept them only in Session memory.
  - If that commit fails, the Run reports the Journal error.
  - After `commitUnknown`, the Session refuses history reads and new Runs until
    it is reopened.
- **Closing gate.** Once `AgentJournal.close()` starts, follow-up enqueue and
  withdrawal fail with `storeClosed`, like other new work.
- **Checkpoint adoption.** The Session adopts a checkpoint whose append returns
  after the Run's deadline or cancellation, instead of failing its next Run
  with `concurrentWriter`.
- **Journal rotation and maintenance.**
  - An uncertain `CURRENT` replacement during rotation poisons the handle
    (`commitUnknown`).
  - While a rotation keeps failing, the active segment is bounded by
    `maxWorkBytes`, with `maintenanceRequired` backpressure.
  - Opening a store with a work budget below its retained data fails with
    `maintenanceBudgetTooSmall(requiredWorkBytes:)`.
  - Schema-4 `pending-operations` indexes are read correctly by maintenance.
  - `create` works under a parent directory reached through a symlink.
- **Writer lock close-on-exec.** A child process that the Host starts with
  `posix_spawn` or fork/exec while a store is open no longer inherits the
  writer lock and keeps the store locked after `close()`. This was reproduced
  on hosted macOS and Linux. Foundation `Process` children were not affected.
- **Typed Core failures.** Core binding, capability and Context errors
  reach events as typed `AgentFailure` cases instead of `unclassified`.

## Breaking changes and Host upgrade

### Journal formats

**New stores are schema 3 by default.** `AgentIncrementalJournal.create(...)`
without options still writes format schema 3. The RC4 reader can open, append
to and maintain it.

**Schema 4 is only for stores that opt in to rejection facts.** A store created
with `supportsAdmissionRejections: true` is schema 4 from creation, before any
rejection is written.
- The unmodified RC4 reader rejects schema 4 at open. It cannot inspect,
  append to or maintain such a store.
- The RC5 reader opens RC4 schema-3 stores for ordinary Runs. A Run that opts
  in to replanning on a schema-3 store fails before any Provider request.

**No automatic migration, upgrade or downgrade.** Neither version converts a
store in either direction.
- A new store does **not** inherit an old store's operation-deduplication
  facts (mutation identities, Receipts, settled replays).
- Stop old writers and resolve their outstanding operations before you start
  a new store for the same work.
- Do not retry an uncertain old mutation under a fresh identity because an
  old store cannot be used.

### New public enum cases

Exhaustive `switch` statements must add these cases, even for Hosts that keep
replanning disabled:

- `AgentEvent.toolAdmissionRejected(ToolCallID)`
- `AgentJournalEvent.toolAdmissionRejected(callID:name:)`
- `AgentSessionError.admissionRejectionJournalRequired`
- `ModelProviderFallbackPolicyError.invalidCandidateIdentity`, thrown by
  `ModelProviderRoute.init` for an empty, over-long, control-character or
  duplicate candidate ID
- `AgentJournalError.maintenanceBudgetTooSmall(requiredWorkBytes:)`
- `AgentFailure.modelBinding`, `.capability`, `.contextPipeline`,
  `.contextProjection`

The example packages add `rejectedBeforeAdmission` (ExecutionReportingSupport)
and `rejected` (AppleChatIntegration) tool states. These packages are not SDK
products.

### Behavior changes

**Route.**
- **Owned continuation state.** The Route records each candidate's
  continuation state in a Route-owned wrapper (`swiftagent.route-candidate.v1`)
  and gives the native state back only to its owner.
- **Refused state.** The Route refuses state it cannot attribute to one of its
  current candidates with `fallbackBlocked`, before any candidate is contacted.
  This covers:
  - state in a history saved by RC4 through a Route;
  - state from candidates created without IDs, after the Route is re-created;
  - mixed-owner state.
- **Keeping state usable.** Give candidates stable IDs with
  `ModelProviderRoute.Candidate(id:provider:)` to keep state usable across
  restarts and reordering.

**Steering.** A cancelled or failed Run whose retained steering cannot be
committed now reports that Journal error, for example `commitUnknown`, from
`wait()` and its terminal event. It no longer reports `CancellationError` or
the Run's own failure.

**Maintenance policy.**
- `JournalMaintenancePolicy` now throws for a `maxWorkBytes` smaller than the
  largest segment rotation can seal. That is `segmentBytes` plus one inline
  frame, which is at most about 683 KiB. RC4 accepted such a policy, and
  maintenance then stalled.
- Opening a store whose retained segments or packs exceed the handle's
  `maxWorkBytes` fails with `maintenanceBudgetTooSmall`, and the store is left
  unchanged.
- While a failed rotation leaves the active segment past `segmentBytes`, Run
  startup, mutation admission and follow-up enqueue fail with
  `maintenanceRequired` until maintenance rotates it.

The [versioning guide](../guides/swift-agent-versioning.md),
[Journal guide](../guides/swift-agent-journal.md) and
[dynamic model selection guide](../guides/swift-agent-dynamic-model-selection.md)
contain the individual contracts.

## Known issues and unfinished evaluation

None of the following is fixed by RC5. Hosts should treat them as open.

- **CI flakes (unattributed).**
  - The hosted macOS job sometimes reaches its 30-minute limit
    ([#45](https://github.com/OtohaCo/SwiftAgent/issues/45)).
  - Hosted Linux `ExecutionReportingSupportTests` segfaulted once
    ([#46](https://github.com/OtohaCo/SwiftAgent/issues/46)).
  - What RC5 adds for these, without claiming a fix:
    - `FollowUpProcessTests` now bounds its child waits. The one local hang
      that was captured with a stack was in that test.
    - CI keeps execution-reporting logs and crash evidence as artifacts.
  - A green rerun is not a fix.
- **Transient `storeInUse` right after close.** If the same process is
  spawning a child process when a store is closed and reopened, the reopen can
  briefly get `storeInUse` until the child starts its new program
  ([#47](https://github.com/OtohaCo/SwiftAgent/issues/47)).
  - The refusal is fail-closed and nothing is leaked.
  - A short retry succeeds.
- **Tracked design and performance items.** None is claimed as a defect.
  - In-memory Journal retention ([#39](https://github.com/OtohaCo/SwiftAgent/issues/39))
  - Per-turn history encoding ([#40](https://github.com/OtohaCo/SwiftAgent/issues/40))
  - Projection revision coordinates ([#41](https://github.com/OtohaCo/SwiftAgent/issues/41))
  - `AgentSession.history` before restore ([#42](https://github.com/OtohaCo/SwiftAgent/issues/42))
  - Resolved read-only projector trust ([#43](https://github.com/OtohaCo/SwiftAgent/issues/43))
  - Low-impact observations ([#44](https://github.com/OtohaCo/SwiftAgent/issues/44))
- **Replanning evaluation.** The deterministic probe and fixtures show only
  the mechanism. The real-model evaluation (`ReplanningEvaluation` live mode)
  was **not run**. Real-model correction rates, latency and Host integration
  are not measured.

## Qualification boundary

The release gate is run on the final tagged commit:

- the repository's macOS and concurrency scripts;
- the strict `BoundedReplanningProbe`;
- the runtime-tools public API regressions;
- the writer-lock and child-process regressions;
- the RC4-reader compatibility matrix;
- hosted macOS, Linux and Apple jobs;
- a clean, credential-free SwiftPM consumer, pinned first to the release
  commit and then to the tag.

The GitHub Pre-release records the exact SHA, tree and results.

One local live check was run, and only this check. On 2026-09-29 the
ProviderQualification `local` provider (`--mode live --case all`) ran against
an LM Studio OpenAI-compatible endpoint on the test machine. The endpoint
reported the model as `qwen/qwen3.8-27b`.
- All 6 cases passed: text, tool, restart, structured, usage and cancel.
- The run made 10 Provider requests.
- It ran on main `5ddb19b`, before the RC5 wrap-up changes, which touch only
  the writer-lock flag, tests, CI and docs.

This does not qualify that model, LM Studio or any other local model beyond
those 6 cases. The local provider produces no continuation state, so Route
isolation is covered only by fixtures.

No paid live Provider request was made. RC5 claims none of the following:
- a production Host dependency update or user-store migration or cutover;
- OS sandbox qualification;
- power-loss simulation.

Disposable-file and `SIGKILL` fixtures verify SDK behavior and process
termination, not physical durability or exactly-once behavior in external
systems. RC5 is an SDK prerelease. It is not production Host approval. Hosts
must qualify their own credentials, resources and deployment.
