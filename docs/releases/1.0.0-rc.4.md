# SwiftAgent 1.0.0-rc.4

> Release type: SDK prerelease candidate. This is not stable 1.0 or a
> production Host/store cutover. The GitHub Pre-release records the exact
> tagged commit and its final-main verification.

RC4 adds four connected SDK capabilities:

- **Segmented Journal:** one local writer owns a store with a persistent
  operation domain. Incremental commits and indexed Session/mutation recovery
  replace full-file reads and repeated conversation snapshots. Trusted intent
  precedes mutation execution; verified Receipt, replayable output and formal
  result publish together. Automatic packing reclaims obsolete process files
  while retaining required facts.
- **Context Pipeline:** Host materials have explicit sources and deterministic
  request-only projection under the existing byte/token budget. A Host-supplied
  summary or read-only excerpt does not replace formal history, grant Evidence,
  or reclassify an earlier mutation.
- **Scoped Capability Binding:** a Run uses one approved tool/backend/resource
  snapshot. Revocation prevents new execution admission while the original
  owner retains cancellation, settlement and physical drain responsibility.
- **Durable Follow-up Queue:** a caller-stable input ID reliably receives
  future FIFO input without injecting it into an active Run. Dispatch is an
  explicit Host action with fresh model/capability approval. Queue admission,
  Run ID and formal user input share one commit. Reopen stays paused; an
  uncertain admitted Run is never automatically replayed.

## Breaking changes and Host upgrade

The final directory format is **schema 3**. Its bounded transaction payload
remains `BatchV2`; separate committed index witnesses and position commit IDs
make missing Session, queue and operation indexes fail explicitly. Schema 1,
the unreleased schema-2 candidate and the old framed Journal file are rejected
unchanged. RC4 has no automatic migration, dual write, reset or durable-to-memory
fallback. Creating a new empty store for an old task does **not** preserve that
task's deduplication ledger; stop old writers and resolve outstanding effects
before defining a new workflow. Do not continue an uncertain old mutation with
a fresh identity merely because the old format cannot be opened.

Rebuild Hosts against the RC4 public API. Old file constructors, full-record
snapshot/persist and manual compaction APIs were removed. Use explicit
`AgentIncrementalJournal.create/open`, throwing paged Journal queries, and
`waitForDrain()` before closing. A poisoned handle may close after drain, but
closing does not decide `commitUnknown`; reopen the same store to inspect the
published root. Follow-up `inputID` is separate from the stable mutation
`operationID`. A queued configuration reference is not authorization: a Host
must supply fresh model, Context and Session-bound capability bindings when
starting dispatch. `run` stays immediate and `steer` stays a current-Run
correction. The [Journal](../guides/swift-agent-journal.md),
[Context](../guides/swift-agent-context.md),
[tool/capability integration](../guides/swift-agent-tools.md) and
[follow-up](../guides/swift-agent-follow-up-queue.md) guides contain the
individual contracts.

The Host can receive each dispatched `AgentRun` through `onRun` and own its
single event observer. Queued Run streams retain at most 256 unconsumed
progress events; a slow observer may lose intermediate events. Trusted
Receipt and replayable output come from the Journal, not an event report.
Terminal input identities, unsettled operations and the information needed to
deduplicate settled operations have no automatic TTL while the operation
domain remains active. Packing removes redundant process files, not retained
formal messages or ledger facts. Real content and identities can grow disk
usage; no fixed upper bound is promised.

## Qualification boundary

The release gate covers the final main commit with the repository's macOS and
concurrency scripts, hosted macOS/Linux/Apple jobs, public ExternalClient and
credential-free fixtures, plus a clean remote SwiftPM consumer pinned to the
release commit and subsequently the tag. Disposable-file mutation and
`SIGKILL` recovery fixtures verify SDK behavior and process termination, not
physical power loss or arbitrary external-system exactly-once. The GitHub
Pre-release supplies exact checkout SHA/tree and results after verification.

No paid live Provider request, production Host dependency update, OS sandbox
qualification, real user-store migration, power-loss simulation or production
storage switch is claimed by this SDK prerelease. Hosts must qualify their own
credentials, resource identities and deployment before production adoption.
