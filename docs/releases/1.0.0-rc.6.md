# SwiftAgent 1.0.0-rc.6 — prepared candidate

Status: **prepared, unreleased**. No release date is assigned and no rc.6 tag
or GitHub Release is created by this delivery. The
[candidate acceptance](rc6-candidate-acceptance.md) identifies the tested source,
PR and actual merged main separately. SDK acceptance does not qualify OtohaAI
or another production Host.

## RC5 → RC6

RC5 target: `24447b8298ccea84f9f8056374857c5c47d8f64c`. This release includes
all merged work since that tag, rather than only audited authorization.
The detailed [CHANGELOG](../../CHANGELOG.md) and
[versioning guide](../guides/swift-agent-versioning.md) remain authoritative
for individual signatures and behavior changes.

- **Host authorization and audit:** opt-in exact prepared-action decisions,
  atomic application/intent and settlement/result references, bounded queries
  and at-least-once archive export with durable prefix acknowledgements.
  Required tool-domain authorization and Evidence remain additional gates.
  Archive data cannot restore live permission. Authorization runs before
  acquiring the scheduler resource lease; expiry and revocation are rechecked.
- **Confirmed no-effect:** opted-in executor proof allows safe model-visible
  correction without replaying uncertain mutation work. Compact versioned
  argument/receipt binding addresses large ordinary inputs; required audit
  still refuses inputs beyond its separate proposal limits. Reconciliation
  needs Host verification, not archival proof or model advice.
- **Context:** stable committed source revision/digest and separate logical
  epoch, reuse of frozen source encoding, whole-group historical read-only
  proof checks, per-request projection and public Host integration example.
  Projection never replaces the formal conversation or mutation ledger.
- **Deferred tools:** bind tools without exposing them until a committed tool
  result declares them. Declaration is Run-scoped and does not grant authority.
- **Durable Runs and queue identity:** optional Run admission/terminal facts
  and indexed lookup; queued inputs can choose per-call or explicit operation
  identity. Logical terminal remains separate from physical drain and later
  trusted reconciliation.
- **Images:** native/description/reject policy with canonical image retention
  and optional image-capable storage. Raw image budgets are independent of
  the final encoded HTTP body limit.
- **Providers:** context overflow classification, stable sorted request JSON,
  typed replay diagnostics, complete DeepSeek native tool retention with and
  without thinking, long-lived URLSession ownership, safety refusal mapping,
  and retry waits only when another attempt remains in both retry budgets.
- **Cache controls and accounting:** Host-qualified Anthropic/OpenAI/Local
  controls, Responses conversation cache keys, optional Anthropic 5m/1h cache
  write detail, sparse replay correctness and coverage-aware cost examples.
  Missing usage and tariffs remain unknown; parameters do not prove cache hits.
- **Storage and CI:** one memory checkpoint per Session, indexed source checks,
  opt-in bounded writer-lock wait with fail-fast default, finite watchdogs and
  retained failures. Linux reporting uses the existing native backend in its
  narrow affected package; the upstream Swift Build defect remains open.
- **Read-only recovery:** existing `.modelVisible` policy now handles invalid
  arguments/output with sanitized feedback and existing Run budgets. Mutation
  and default fail-closed paths retain their safety boundary.
- **Final answer:** an answer fully received before deadline can complete its
  durable publication after deadline. Publication failure or uncertainty is
  still an error, and steering into a new model round restores deadline checks.
- **Optional examples:** public Jev Decision evaluation, capability and audit
  Hosts, bounded deterministic fixtures. Native OpenAI Decisions is not
  implemented; ordinary Responses is not a substitute protocol.

## RC6 closeout

The closeout rejects stale persistent Session baselines before new input
admission, checks Anthropic's actual serialized body before transport, and
rejects unsupported signed-thinking prefix changes before dispatch. Tests
cover real file publication crossing deadline and a fixed projector whose
source-correct request view changes within one Run. See the acceptance page
for results and remaining qualification limits.

## Compatibility and storage

RC6 is a prerelease with public source and runtime changes. Exhaustive switches
must account for new failure/event/content cases. Defaulted added parameters
can break stored initializer function references even when ordinary calls
compile. New optional Codable fields decode older documents only where the
specific API documents that behavior; do not assume archival proof grants
runtime permission. Cache detail overloads and provider error overloads retain
their documented old function signatures. Review the complete versioning guide.

| Creation option | Selected schema / capability |
| --- | --- |
| Default | 3; ordinary durable history/mutations |
| Admission rejections | 4 |
| Authorization audit | 5, including rejection support |
| Original confirmed-no-effect stores | 6/v1 readable; not silently upgraded |
| Confirmed no-effect new stores | 7/v2 compact proof, including prior capabilities |
| Per-call follow-ups | 8, including prior capabilities |
| Run records | 9, including prior capabilities |
| Image content | 10, including prior capabilities |

Creation flags determine the highest required format; existing stores are not
migrated, downgraded or rewritten to obtain capabilities. Actual pinned readers
verify rejection of unsupported formats before append and maintenance. RC5
still reads compatible default schema 3; it cannot interpret new opt-in
formats. New readers preserve supported older facts. A new store does not
inherit operation identities or Receipts from an old one. Never replay an
uncertain mutation under a fresh identity to bypass recovery.

## Provider and Host limits

See the [Anthropic guide](../guides/swift-agent-anthropic-provider.md),
[context guide](../guides/swift-agent-context.md) and [Host integration guide](../guides/swift-agent-host-context.md)
for the local support/rejection matrix. Fixtures do not qualify a current
service/model/account. No new paid live calls are part of RC6 closeout.
Previously recorded cache qualification (#86–#89) is retained with its exact
endpoint/account and sample limits; it is not rerun or generalized.

Known follow-ups remain open: streaming accumulation optimization (#44),
historical hosted timeout attribution (#45), upstream Linux planning crash
and workaround migration (#46), the OS pre-exec lock window (#47), authoritative
native Decisions protocol (#60), and Jev full-response allocation bounds (#61).
These do not grant broader production transport or qualification guarantees.
Automatic summaries, RAG, project memory, summary caches, current-Run built-in
tool-output excerpt expansion and durable historical effect provenance require
separate designs. RC6 does not restore lossy canonical-history compaction.

OtohaAI integration is a separate task: select and pin the accepted SDK,
configure Host thresholds/budgets, source/cache versions and projector,
handle local provider rejections and fresh-Session recovery, then run product
end-to-end acceptance. No OtohaAI code or pin changes are made here.
