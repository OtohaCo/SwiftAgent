The tested starting point was main `3f01599ef3d0923659226025a7d34d4144ed1800` (tree `9aa6e6828e01aa4d7b1b6ac3689fa89ac6a26989`) and #26 head `5d792457a2b39f712e5f7279d51cb081c1080693` (tree `13d503a16425886004fc82a7592589c97cbc8e0b`). The workspace was clean before creating `codex/bounded-pre-admission-replanning`. ## Policy and evidence boundary

`AgentConfiguration(preAdmissionReplanning: .evidenceRejection(toolNames: ["commit_resource"]))` opts in one named mutation tool. The capable durable store must be created with `supportsAdmissionRejections: true` (schema 4); an opt-in Run on a schema-3 store fails before Provider contact. The default `.disabled` and default schema-3 creation keep the RC4 failure behavior. A single prepared call uses the runtime's own Evidence ledger before authorization, intent or final admission; the normal invocation repeats all checks. A trusted denial is not an executor error, successful tool completion, mutation Receipt or read-only result proof. The typed rejection marker and formal assistant-call/error-result pair are committed together. A failed or unknown commit terminates before another Provider request. The payload is limited to a code and a bounded form of the submitted reference; it says execution was denied, not authorized.

The correction consumes one rejected call attempt and one feedback opportunity in the original Run. The existing model-turn and tool-call limits, deadline, scope generation and operation identity remain in force. Only a short, safe reference already supplied as a model argument is repeated in feedback; Host-computed reference identities are not exposed. Pending state is checked for the Session and same logical operation; a failed query closes the route. A previous mutation effect or trusted replay in this Run also closes it. Multi-call batches, authorization, scope, schema, Journal, Receipt, executor and post-effect failures retain their existing failure or reconciliation path.

Normal tests and the strict executable are both CI requirements on macOS and Linux. The schema-4 capable store is a post-RC4 Journal reader compatibility boundary, documented in [ADR 0008](../adr/0008-bounded-pre-admission-replanning.md) and the [versioning guide](../guides/swift-agent-versioning.md). The [targeted independent review](pr27-targeted-review.md) includes cross-process marker recovery, actual RC4 reader results and operation query measurements. RC4's original [measurement record](bounded-replanning-rc4.md) remains historical evidence, not a claim about this opt-in build.

This fixture proves only that a scripted model which sees the linked feedback can complete the two paths. Real LLM correction rate, music recommendations, point-to-play p50/p95, device playback, paid Providers and production Host integration are **NOT RUN**. The public API cannot observe an independent input ID for direct `Session.run`, so that ID is **NOT OBSERVED**. No production Host retry was invoked.
